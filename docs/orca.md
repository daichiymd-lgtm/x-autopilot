# Orca 導入メモ（x-autopilot）

## 1. Orca とは
- 複数の AI コーディングエージェント（Claude Code・Codex など）を、1つのアプリで並行に動かすデスクトップアプリ
- 作業ごとに git の作業スペース（worktree）を分けるので、AI 同士が同じファイルを壊し合わない
- モデルの利用は既存の Claude Code などの契約をそのまま使う（Orca がモデル利用を中継するわけではない）
- 開発元: Stably AI／ライセンス MIT／[GitHub](https://github.com/stablyai/orca)

## 2. 本人がやること（3ステップ・約5分）
AI が代わりにできないのはここだけです（PC へのアプリのインストールのため）。

1. **インストール**（Mac の例。どちらか1つ）
   - Homebrew: `brew install --cask stablyai/orca/orca`（`orca` だけだと別のアプリになるので、この名前のまま）
   - または [orca.dev/download](https://orca.dev/download) から dmg を入れる
2. **初回起動**：ホームフォルダへのアクセスを許可。`~/.claude` の取り込みを聞かれたら「取り込む」
3. **リポジトリを追加**：サイドバーの **Add Repo** → PC 上の `x-autopilot` を選ぶ → リポジトリ名の横の **+** で作業スペースを作り、エージェントに Claude Code を選ぶ

初回は「`orca.yaml` のコマンドを実行してよいか」の確認が出ます。中身は下の「3」で、承認して問題ありません。

## 3. このリポジトリ側で用意済みのこと（`orca.yaml`）
作業スペースを作るたびに自動で次が走り、全部通ってから AI が起動します。

| 順 | 内容 | 失敗したとき |
|---|---|---|
| 1 | `config.yaml` の `publish.frozen: true` を確認 | 止まる（AI は起動しない） |
| 2 | 環境変数 `X_AUTOPILOT_FROZEN=0` が無いことを確認 | 止まる |
| 3 | 作業スペースに `.env`（APIキー）が無いことを確認 | 止まる |
| 4 | 作業スペース専用の `.venv` に依存を入れる | 止まる |
| 5 | `tests/smoke.py`（ネットワーク不要）を実行 | 止まる |

狙い：AI を何体並べても、このリポジトリからは Grok・Claude API・X API の課金が起きない状態にする。

## 4. 検証の記録（2026-11-17・クラウド環境で再現）
Orca の準備処理と同じ条件（新しい worktree・Bash・`set -e`）で実行した結果。

| ケース | 期待 | 結果 |
|---|---|---|
| 通常 | 通過・テストOK | 通過（スモーク全項目OK） |
| `X_AUTOPILOT_FROZEN=0` | 停止 | 停止 |
| `.env` がある | 停止 | 停止 |
| `frozen: false` | 停止 | 停止 |

未確認：Orca アプリ本体での実際の動作（このセッションから PC に接続できないため）。

## 5. 使い方のコツ
- 同じ依頼を Claude Code と Codex に並べて出し、差分を見比べて良い方を採用する
- 差分の行に直接コメントして、その AI に直させる
- 本番の X 投稿は別ライン `note-x-daily-post`。このリポジトリでは投稿を再開しない
